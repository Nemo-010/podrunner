A beta of podrunner, for tests. It is not for production CI.

podrunner runs each CI job of GitHub (or of another forge) in one fresh
unit and destroys the unit after the job. It needs no root and no
docker daemon. Each binary is static (musl).

## What is new since v0.1.0-beta.4

The local mode (`podrunner run`, as nektos/act) runs a workflow of a
local tree with the official runner, in a unit of the `podvm`,
`microvm` or `incus` kind, or in a runner directory:

* Actions by tag in a store with a lock file (`--offline`, `--frozen`),
  fetched through the egress module; actions of a local directory
  (`--local-repository`) and of another action server.
* Reusable workflows (`jobs.<id>.uses`), matrices, `needs`, `if:`,
  `fail-fast`, `continue-on-error`, `concurrency` groups, environments
  with their secrets, vars, egress policy and protection.
* The event payload, the filters of `on:`, `workflow_dispatch` inputs,
  `on.schedule` and `--watch`; a directory of workflows
  (`podrunner run DIR`).
* `services:`, a job container, Docker actions and Dockerfile actions in
  a `microvm` guest with an engine (`--engine DIR`). The engine takes the
  pinned images of Docker Hub from the store through the broker, its
  mirror.
* Container images by tag, pinned by digest in the lock file.
* Artifacts v4, `actions/cache`, OIDC id-tokens, the job summary, live
  logs, `--json`, a log directory, a web view on the loopback.
* Jobs in parallel (`--jobs N`); a rerun of the failed jobs.
* A pause before a step (`--break JOB:STEP`) or after a failed step
  (`--break-on-failure`, `--keep-failed`), with a shell in a `podvm` unit
  or an `incus` instance.
* `--export DIR` (the workspaces of each job) and `--toolcache DIR` (a
  read-only tool cache) on `--podvm`.
* `--platform LABEL=IMAGE` gives a runner image to a label of `runs-on`.
  A larger image with the common tools of `ubuntu-latest` is the
  artifact `runner-full-x86_64` of `runner-image.yml`.
* `podrunner doctor --run` checks a host for the local mode.

Other changes:

* podvm `v0.2.0-beta.18`, podcrates `v0.47.0`.
* A job of another architecture fails by name before a runner starts.

## What is proven in CI

* The parity suite of the local mode (`crates/podrunner/tests/local/parity`):
  each row passes in `microvm` guests with an engine, and on a runner
  directory.
* The local suite on the `podvm`, `microvm` and `incus` kinds; the export,
  the tool cache, the larger image, an image by tag, and the images of a
  guest engine from the store with no registry host allowed.
* The kinds as in beta.4: the unit conformance tests on the `podvm`,
  `microvm` and `incus` kinds, and the official runner v2.338.2 in each.

## What is not proven

* No job of real github.com or of githome ran yet. The live gates
  (T-032, T-033, T-040) run on test hosts.
* A static image (the memfd family of podvm) as a container of a `podvm`
  unit (T-158).
* A `microvm` guest has no shell at a pause: podvm refuses `exec` there.

## The files

| File | What it is |
| --- | --- |
| `podrunner-x86_64-unknown-linux-musl` | podrunner, Linux x86-64 |
| `podrunner-aarch64-unknown-linux-musl` | podrunner, Linux ARM64 |
| `scaleset-sidecar-x86_64-unknown-linux-musl` | the sidecar of a `github-scaleset` source, Linux x86-64 |
| `scaleset-sidecar-aarch64-unknown-linux-musl` | the sidecar, Linux ARM64 |

Each file has a `.sha256` file and a build provenance attestation.

```sh
sha256sum -c podrunner-x86_64-unknown-linux-musl.sha256
gh attestation verify podrunner-x86_64-unknown-linux-musl --repo PodUtils/podrunner
```

A unit also needs:

* podvm `v0.2.0-beta.18` (`images/podvm.toml` gives the SHA-256 of each
  binary); the `microvm` kind needs QEMU, and the `incus` kind an
  incusd;
* podnet `v0.4.0-beta.8` for the egress hold of the podvm kind
  (`images/podnet.toml`);
* the runner image: build it with `images/runner/Dockerfile`, or take
  the archive `runner-x86_64` or `runner-aarch64` of the
  `runner-image.yml` run of the tagged commit, and `podvm load` it.

## Report a problem

Open an issue in `PodUtils/podrunner` with the command, its output, and
the output of `podrunner doctor --json`. Do not put a key, a token or a
credential file in the issue.
