A beta of podrunner, for tests. It is not for production CI.

podrunner runs each CI job of GitHub (or of another forge) in one fresh
unit and destroys the unit after the job. It needs no root and no
docker daemon. Each binary is static (musl).

## What is new since v0.1.0-beta.6

* The scale-set sidecar cancels the workflow run of a job that podrunner
  refuses (for example a tier mismatch or an untrusted owner), so a fork
  pull request does not hold the capacity of a trusted scale set (T-169,
  the ruling Q7 of the owner). The App needs the repository permission
  "Actions: read and write". A refusal for a wait deadline, a cancel or a
  conformance check does not cancel the run.
* A unit applies the limits of its offer: `memory`, `cpu` and `pids` of
  pod-job, the lesser of the offer and of `[unit.KIND]` (T-198). The
  podvm kind applies `memory` and `pids`, the incus kind all three; the
  microvm kind keeps the size of its guest.
* The report of a job comes before its `release`, also for a claimed job
  that could not start and for a job that a restart lost: at the
  `release`, a source knows whether podrunner refused the job. The source
  contract says how a job ends at the source (T-200).
* The job-started hook of the runner image writes an annotation that
  names the cause when it ends a foreign job (T-201).
* podcrates `v0.51.0`.

## What is proven in CI

* The tests of the sidecar against a fake scale set: the cancel of the
  run of a refused job, one for each run.
* On a podvm unit and an incus instance: a payload past `memory` and one
  past `pids` of an offer get an error, and the runner runs under the
  limits of a podvm unit.

## What is not proven

* The live gates (T-032, T-033, T-040) run on test hosts.
* The cancel of a refused run on github.com (GitHub #74, #121).
* On a host with no user namespace (H0), the runner timed out on the
  broker in the first live run (T-179).

## The files

| File | What it is |
| --- | --- |
| `podrunner-x86_64-unknown-linux-musl` | podrunner, Linux x86-64 |
| `podrunner-aarch64-unknown-linux-musl` | podrunner, Linux ARM64 |
| `scaleset-sidecar-x86_64-unknown-linux-musl` | the sidecar of a `github-scaleset` source, Linux x86-64 |
| `scaleset-sidecar-aarch64-unknown-linux-musl` | the sidecar, Linux ARM64 |

Each file has a `.sha256` file and a build provenance attestation.

```sh
sha256sum -c podrunner-x86_64-unknown-linux-musl.sha256
gh attestation verify podrunner-x86_64-unknown-linux-musl --repo PodUtils/podrunner
```

A unit also needs:

* podvm `v0.2.0-beta.21` (`images/podvm.toml` gives the SHA-256 of each
  binary); the `microvm` kind needs QEMU, and the `incus` kind an
  incusd;
* podnet `v0.4.0-beta.8` for the egress hold of the podvm kind
  (`images/podnet.toml`);
* the runner image: build it with `images/runner/Dockerfile`, or take
  the archive `runner-x86_64` or `runner-aarch64` of the
  `runner-image.yml` run of the tagged commit, and `podvm load` it.
