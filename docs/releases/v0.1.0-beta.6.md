A beta of podrunner, for tests. It is not for production CI.

podrunner runs each CI job of GitHub (or of another forge) in one fresh
unit and destroys the unit after the job. It needs no root and no
docker daemon. Each binary is static (musl).

## What is new since v0.1.0-beta.5

The fixes of the first live run (GitHub #74, #75 and #116 to #147):

* The scale-set sidecar holds the long poll of GitHub in the background,
  so `next` answers in its time limit; it reads the `JobAssigned`
  messages that github.com sends; it reads `private` when the
  visibility of a run is null; it names the class of each error; it
  closes its message session at its end.
* `sign` gives its last token again to a restarted sidecar, and only a
  `next` that passed resets the backoff; each request of `sign` is a
  line of the log.
* The runner image ends a job other than the one placed in its unit
  before its first step (a job-started hook): GitHub binds no runner of
  a scale set to one job.
* A refused offer is withdrawn with an audit line; a bad offer is
  `bad-request`; a refused job that a source offers again is withdrawn
  again.
* `serve` pulls a container image that a digest pins; it names the
  cause of a failed hook call and of a failed start; it does not stop
  when a unit fails during a hook call; `status` answers while `serve`
  waits on a source; as PID 1 of a container it forks a reaper.
* The runner on the `incus` and `microvm` kinds has its own `HOME`.
* Limits of memory, CPU and processes for each unit kind
  (`[unit.KIND] mem`, `cpus`, `pids`).
* `podrunner check` reads a mint file, and refuses a file that no kind
  can serve; `doctor` reads the egress hold as `serve` does, and names
  why a source is not served.
* `[trust] users`, for a forge with repositories of a person.
* `--version` names the beta.

Other changes:

* podvm `v0.2.0-beta.21` (a static image with a read-only volume where
  chroot is denied), podcrates `v0.50.0`.

## What is proven in CI

* The tests of the sidecar against a fake scale set that sends
  `JobAssigned` messages and the minimal repository of a run.
* In a `podvm` unit: a static image as a job container, the job-started
  hook (a foreign job ends with no step), and the runner under the
  limits of the unit.
* The kinds as in beta.5.

## What is not proven

* The live gates (T-032, T-033, T-040) run on test hosts with this beta.
* A job that the tier rule refuses still holds the capacity of the scale
  set at GitHub (T-169: waits for a ruling of the owner).
* On a host with no user namespace (H0), the runner timed out on the
  broker in the live run (T-179): the log now names the stage of each
  failed connection.

## The files

| File | What it is |
| --- | --- |
| `podrunner-x86_64-unknown-linux-musl` | podrunner, Linux x86-64 |
| `podrunner-aarch64-unknown-linux-musl` | podrunner, Linux ARM64 |
| `scaleset-sidecar-x86_64-unknown-linux-musl` | the sidecar of a `github-scaleset` source, Linux x86-64 |
| `scaleset-sidecar-aarch64-unknown-linux-musl` | the sidecar, Linux ARM64 |

Each file has a `.sha256` file and a build provenance attestation.

```sh
sha256sum -c podrunner-x86_64-unknown-linux-musl.sha256
gh attestation verify podrunner-x86_64-unknown-linux-musl --repo PodUtils/podrunner
```

A unit also needs:

* podvm `v0.2.0-beta.21` (`images/podvm.toml` gives the SHA-256 of each
  binary); the `microvm` kind needs QEMU, and the `incus` kind an
  incusd;
* podnet `v0.4.0-beta.8` for the egress hold of the podvm kind
  (`images/podnet.toml`);
* the runner image: build it with `images/runner/Dockerfile`, or take
  the archive `runner-x86_64` or `runner-aarch64` of the
  `runner-image.yml` run of the tagged commit, and `podvm load` it.
